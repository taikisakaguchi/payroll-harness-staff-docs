給与計算ハーネス 運用マニュアル

Claude Code ではじめる給与チェック
— スタッフ向け運用マニュアル

このページは、事務所スタッフが Claude Code（デスクトップアプリの「Code」タブ）で給与計算ハーネスを回すための手順書です。内部の仕組みを知らなくても、「決まった操作 → 日本語の指示が返る → 指示に従う」の流れで月次が完了するように書いています。

TL;DR

  1. 作業は必ずデスクトップアプリの「Code」タブで、担当会社のフォルダを開いてから始める。Chat タブではハーネスが動かない。
  2. 月次は 7 段階。スタッフの担当は「変動事項の記入 → 勤怠 CSV 配置 → チェック実行 → アラート潰し」の 4 つ。
  3. 🔴 の判断に迷ったら推測せず所長へエスカレーション。台帳の削除・設定ファイルの書き換えは禁止。

01ハーネスの役割 — 「計算」はしない、「確認」を支える

まず前提として、このツールが何をして・何をしないかを押さえます。

給与計算そのものは、これまでどおり給与計算ソフト（OS給与）が行います。ハーネスの役割は、その結果をチェック（レビュー）することと、人の記憶に頼りがちな管理（変動事項の反映確認・有給・随時改定）を台帳で支えることです。

位置づけは「自動化ツール」ではなく「伴走ツール」。最終確認は必ず人の目で行います。ハーネスは、その確認が漏れなく・楽にできるようにするための道具です。

担当やること
OS給与給与計算の本体（支給額・控除額の計算）
ハーネス（Claude Code）計算結果のチェック、変動事項・有給・随時改定の台帳管理、アラート出力
スタッフ（あなた）変動事項の記入、勤怠データの配置、チェックの実行、アラートの確認
所長判断が必要な事項の決定、最終確定・納品

02作業場所は「Code」タブ — Chat タブでは動きません

Claude デスクトップアプリには 3 つのタブがあり、給与業務で使えるのは 1 つだけです。

タブ何ができるか給与業務で使う？
Chatふつうの Claude との会話。会社フォルダのルール・チェック機能は一切読み込まれない使わない
Cowork長時間タスクの自動実行。こちらも会社フォルダの設定は読まない使わない
Code会社フォルダのルール（CLAUDE.md）・チェックスクリプト・安全装置がすべて有効ここで作業する

Chat タブで給与の質問をしないでください。会社ごとのルールや台帳を読まない「素の Claude」が、それらしい一般論を答えてしまいます。給与に関する質問・作業は、必ず Code タブで会社フォルダを開いてから行います。

開き方は毎回同じです:

  • Claude デスクトップアプリを起動する
  • 上部の「Code」タブを選ぶ
  • 担当会社のフォルダを開く（最近開いたフォルダから選べます）
  • 画面にいま開いているフォルダ名が出ているので、会社名が正しいか確認してから作業を始める

03初回だけの準備 — フォルダを開いて「信頼」する

各会社フォルダを初めて開くときだけ、1 回だけの確認があります。

初めて会社フォルダを開くと、「このワークスペースを信頼しますか？」という確認画面が表示されます。ここで「信頼する」を選んでください。これはフォルダに入っているチェック機能・安全装置を有効にするための確認で、許可しないとハーネスが動きません。表示されるのは会社フォルダごとに初回の 1 回だけです。

1 社 1 フォルダが鉄則です。A 社の作業は A 社のフォルダで、B 社の作業は B 社のフォルダで行います。会社をまたいで作業すると、顧問先間の情報が混ざる事故につながります。

アプリへのログインや契約プランは事務所側で設定済みです。確認画面が何度も出る・エラーで先に進めない場合は、自分で対処せず所長へ連絡してください。

04月次の流れ — 7 段階を順番に

1 か月の給与業務は、この 7 段階で回します（詳細の正本は docs/月次運用フロー.md）。

段階実行者やること
[1] 随時スタッフ昇給・入退社・休職などの変動事項を変動事項入力シート.xlsx に記入する
[2] 締め後スタッフ勤怠ツール（OS勤怠）から出した勤怠 CSV を所定の場所に置く
[3]Claude Code取込用データを生成する（スクリプトが自動で処理）
[4]スタッフ生成されたデータを OS給与へ一括取込（マスタ変更は画面から入力）
[5]Claude Code給与チェックを実行し、アラート一覧を出力する
[6]スタッフ + 所長アラート一覧_YYYY-MM.xlsx の 🔴 🟡 📋 と照会事項をすべて潰す
[7]所長確定・納品

入社・退職があった月は、次の 2 点だけ特別扱いです:

  • 入社: まず所長に台帳作成を依頼 → 変動事項シートに「入社」行を記入 → OS給与にマスタ登録
  • 退職: 台帳は絶対に削除しない。状態を「退職」に変えるだけ（源泉徴収票・離職票の根拠として保管し続けます）

05スタッフがやる操作 — 頼み方とコマンド

操作は「日本語で頼む」が基本です。コマンドは覚えなくて構いません。

Code タブで会社フォルダを開いたら、やってほしいことをそのまま日本語で入力します。例:

「2026年8月分の給与チェックを実行して」
「変動事項シートの内容を台帳に取り込んで」

Claude Code が対応するスクリプトを実行し、結果と次にやることを日本語で返します。参考までに、裏で動いている代表的なコマンドは次の 2 つです:

# 月次の給与チェック（all のほか payroll / ledger 単体も可）
PAYROLL_DB=<台帳パス> ruby scripts/payroll_check.rb all 2026-08

# 変動事項シートの取込
PAYROLL_DB=<台帳パス> python3 scripts/build_events_from_excel.py import 変動事項入力シート.xlsx

完了の合図は「ファイルができていること」です。「完了しました」という言葉ではなく、アラート一覧_YYYY-MM.xlsx が実際に生成・更新されていることを確認してから次の段階へ進みます。

06アラートの読み方 — 🔴 🟡 📋 と照会

チェック実行後のアラート一覧は、マークごとに対応が決まっています。

マーク意味誰が・どう対応する
🔴 要対応金額や手続きに影響がある指摘内容を確認。自分で判断できるものだけ対応し、迷ったら所長へエスカレーション
🟡 注意読んで確認すればよい注意喚起スタッフが内容を確認して消し込む
📋 未整備台帳側のデータ不足スタッフが不足データを台帳・シートに補充する
照会顧客・所内に確認が必要な事項スタッフが確認して回答を記入。来月以降に影響する内容なら所長の承認が必須

07所長へ回す条件 — エスカレーション

次のどれかに当てはまったら、対応状況を「エスカレーション」にして所長へ回します。

  • 🔴 の内容が自分では判断できないとき
  • 照会の結果、昇給・入退社・休職・育休など来月以降に影響する内容だと分かったとき（所長の承認が必須）
  • 変動事項シートの種別リストにない出来事が起きたとき
  • エラーや確認画面が繰り返し出て先に進めないとき

迷ったら聞く、が正解です。私たちの仕事の価値は「人の目で確認したこと」の担保にあります。推測で進めることは、確認したことにはなりません。

08やってはいけないこと

事故につながるため、次の操作は禁止です。困ったら所長へ。

禁止事項理由
Chat / Cowork タブで給与業務をする会社のルール・チェック機能を通らない回答が返り、誤った処理の元になる
設定ファイル（config/company.yaml など）を書き換える会社の就業規則・料率のパラメータ。変更は所長の判断事項
退職者の台帳を削除する源泉徴収票・離職票の根拠として永続保管が必要。状態を「退職」に変えるだけにする
別会社のフォルダで作業・実行する顧問先間の情報混在につながる。1 社 1 フォルダが鉄則
アラートが残ったまま確定依頼を出す[6] のアラート潰しが完了条件。未消化のまま [7] に進まない

結論

  1. 「Code」タブ + 担当会社フォルダが、すべての作業の起点（1 社 1 フォルダ）。
  2. 完了は「完了しました」の言葉ではなく、生成されたファイル（アラート一覧など）で確認する。
  3. 迷ったら所長へ。推測とマニュアル外の操作はしない。
